# 어려운 핵심 로직 다루기

과제의 어려움이 화면이 아니라 "규칙을 지키면서 더 나은 답을 찾는 계산"에 있을 때 본다.
정답이 하나가 아닌 문제는 "어떤 기준으로 더 낫다고 판단했고, 그걸 어떻게 확인했나"를 설명할 수 있으면 된다.

## 진행 순서

1. 쪼개기: 큰 문제를 하위 문제 2~5개로 나눈다. 하위 문제마다 입력과 출력을 한 줄로
2. 규칙과 목표를 나눈다
   - 지켜야만 하는 것(하드 제약): 어기면 결과가 틀린 것
   - 더 좋게 할 것(목표): 점수로 비교할 것. 여러 개면 우선순위나 가중치를 결정 카드로
3. 검증기를 먼저: 과제 문서의 규칙만 보고 결과를 검사하는 코드(checks/). 코어 로직과 독립이라 어떤 알고리즘이든 같은 잣대로 잰다
4. 기준선: 하위 문제마다 가장 단순하게 규칙을 지키는 방법으로 끝까지 한 번 돌린다. 여기까지가 "제출 가능한 상태"
5. 개선: 기준선과 같은 점수 기준으로 비교한 수치를 남긴다 (DECISIONS 결정 카드의 "확인 방법과 결과")
6. 시간 상한: 계산은 몇 초 안에 끝나게 반복 횟수나 시간 제한을 둔다. 화면에서 한 번 누를 때 수 분씩 걸리면 검증을 못 한다

서비스 구조는 이 틀로 잡으면 코어 로직만 갈아끼울 수 있다:
`요청 검증 → 코어 로직(함수 하나) → 결과 검증(검증기) → 저장·응답`

## 문제 모양별 후보 (기준선 → 개선)

| 문제 모양 | 기준선 (먼저) | 개선 후보 (시간 남으면) |
| --- | --- | --- |
| 여러 대상을 그룹·자원에 나눠 담기 (용량 제한) | 큰 것부터 넣기, 가까운 곳에 넣기 같은 탐욕법 | 지역 탐색(바꿔 보고 좋아지면 유지), 최소 비용 배정 |
| 순서·경로 정하기 | 가장 가까운 다음 지점부터 | 두 구간 뒤집어 보기(2-opt), 삽입 위치 바꾸기 |
| 일정·시간 배치 | 마감·시작 순 정렬 후 순서대로 | 우선순위 큐, 충돌 시 되돌리기 |
| 위치 몇 곳 고르기 (최대한 덮기) | 가장 많이 덮는 곳부터 하나씩 | 바꿔 보기 탐색, 군집(k-means) 중심 활용 |
| 일대일 짝짓기 | 점수 높은 쌍부터 | 헝가리안(최소 비용 배정) |
| 최단 거리·연결 | 너비 우선 탐색(BFS) | 다익스트라 |
| 추천·순위 | 인기순, 규칙 기반 점수 | 유사도 기반, 가중치 조정 |
| 이상·위험 판정 | 고정 기준값, 규칙 표 | 통계 기준(평균±표준편차), 여러 규칙 점수화 |
| 조건이 많은 조합 | 규칙 순서대로 걸러내기 | 백트래킹, 최적화 라이브러리 |

최적화 라이브러리(OR-Tools, PuLP 등)는 설치 시간과 "내가 설명할 수 있나"를 결정 카드로 따진 뒤에만 쓴다.

## Codex에 보낼 말

쪼개기와 후보 받기
```text
PLAN의 핵심 요구(★)를 하위 문제로 나눠줘. 하위 문제마다 입력·출력 한 줄, 하드 제약과 개선 목표를 구분해.
그리고 하위 문제마다 알고리즘 후보를 AGENTS.md 결정 형식으로: 가장 단순한 기준선 1개 + 개선 후보 1~2개.
각 후보에 시간 복잡도, 이 데이터 규모에서 예상 실행 시간, 내가 설명하기 쉬운 정도를 붙여. 구현은 하지 마.
```

검증기 먼저
```text
과제 문서의 규칙(R 번호)만 근거로 결과를 검사하는 검증기를 checks/에 만들어줘. 코어 로직 코드는 보지 마.
규칙마다 일부러 어긴 작은 예시로 검증기가 실패하는 테스트도 같이.
```

비교
```text
기준선과 개선안을 같은 입력, 같은 점수 기준으로 돌려서 표로 비교해줘: 규칙 위반 수, 목표 점수, 실행 시간.
결과는 notes/에 파일로 저장하고 화면에는 요약만.
```

추천 근거 묻기 (바로 받지 않는다)
```text
(하위 문제)에 (추천 알고리즘)을 고른 근거를 이 데이터 기준으로 설명해줘. 쉬운 말로, 작은 예시 하나로.
다른 후보보다 나쁜 경우는 언제인지도.
```

작게 실측하고 조합하기
```text
후보들을 작은 데이터(하루치, 한 그룹)로 짧게 돌려서 규칙 위반 수, 점수, 실행 시간을 비교해줘. scripts/에 비교 스크립트로.
고른 하위 로직은 각각 작은 스크립트로 먼저 확인하고, 확인된 것끼리 코어 로직으로 합쳐.
```

## 막혔을 때

- 20분 넘게 같은 문제에 막히면 멈춘다: 기준선으로 돌아가 제출 가능한 상태를 지키고, 막힌 부분은 가정·한계로 기록한다
- 결과가 이상하면 작은 입력(사람이 손으로 셀 수 있는 크기)으로 기대값을 먼저 정하고 비교한다
- 계산이 느리면 데이터 전체가 아니라 하루·한 그룹 단위로 나눠 계산할 수 있는지 본다
