# 운영 환경 준비 점검표

과제가 운영·배포·컨테이너·재시작 같은 조건을 말할 때만 본다. 과제가 요구하지 않은 항목은 만들지 않는다(과잉 구현).
요구된 항목은 첫 뼈대 단위에 넣는다. 끝에 붙이면 시간이 없다.

| 분류 | 항목 | 확인 방법 |
| --- | --- | --- |
| 설정 | 포트, 접속 정보, 비밀값을 코드 밖(환경변수)에서 받는다. 예시 설정 파일을 둔다 | check.sh 비밀값 검사, 예시 파일만 보고 실행해 보기 |
| 설정 | 진짜 비밀값 파일은 git에 넣지 않는다 | check.sh |
| 실행 | 외부에서 접속되게 0.0.0.0에 바인딩 | 미리보기 접속 |
| 실행 | 의존성을 파일로 고정한다 (requirements, lock 파일 등) | 새 환경에서 설치 명령 한 줄로 되는지 |
| 실행 | 컨테이너로 실행하라면 빌드가 처음부터 깨끗하게 된다 | check.sh full |
| 상태 | 살아 있는지 확인하는 주소가 있다면 저장소 연결까지 본다 | curl 로 호출 |
| 데이터 | 저장해야 하는 건 프로세스 밖(DB, 볼륨)에 저장되어 재시작해도 남는다 | 넣고 → 재시작 → 같은 값 조회 (checks/full/) |
| 데이터 | 처음 기동할 때 필요한 구조가 자동으로 준비되고, 두 번 기동해도 망가지지 않는다 | 저장소를 비우고 기동, 한 번 더 기동 |
| 보안 | 권한이 필요한 기능은 화면이 아니라 서버에서 막는다 | 권한 없는 요청을 직접 보내 거부되는지 |
| 운영 | 오류는 로그로 남기되 비밀값은 찍지 않는다 | 로그 훑기 |
| 문서 | 실행 문서만 보고 다른 사람이 실행할 수 있다 | 문서 순서대로 직접 따라 쳐 보기 |

재시작 확인이 실패하면 데이터가 사라진 건지 연결이 바뀐 건지부터 나눈다. 컨테이너를 다시 띄우면 포트나 주소가 바뀌어 연결만 실패하는 경우가 있다.
