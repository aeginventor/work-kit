# 과제 성격별 첫 수

02에서 정한 작업 유형(만들기, 고치기 …)과 별개로, 과제가 "무엇을 다루는지"에 따라 먼저 물을 것과 검증이 달라진다.
과제를 읽고 가장 가까운 성격 하나를 고른다. 섞여 있으면 핵심 요구(★)에 가까운 쪽.

## 배치·편성 (규칙을 지키며 나누고 배정하기)
예: 강의 시간표 배정, 창고 적재, 회의실 예약 배정
- 먼저 물을 것: 절대 어기면 안 되는 규칙 / 더 좋게 할 목표와 우선순위 / 한 사람·한 곳이 크게 손해 보는 경우의 허용 범위
- 첫 단위: 규칙 검증기 + 규칙만 지키는 단순 배정
- 검증: 규칙 위반 0건, 기준선 대비 목표 점수 비교표
- 함정: 평균만 보고 최악의 경우를 놓침, 날짜·시간 경계, 조건 변경 시 다시 계산 안 됨
- 더 보기: ref/algorithm.md

## 추천·순위
예: 상품·콘텐츠 추천, 우선순위 목록
- 먼저 물을 것: 성공을 무엇으로 보나(클릭, 구매, 만족) / 절대 추천하면 안 되는 것 / 기록이 없는 새 사용자는 어떻게
- 첫 단위: 인기순 같은 단순 기준선과 평가 지표 계산 코드
- 검증: 같은 데이터로 기준선과 비교, 제외 규칙 위반 0건, 새 사용자 처리
- 함정: 평가에 쓴 데이터를 학습에도 써서 점수가 부풀려짐, 추천 이유를 설명 못 함

## 규칙·심사·운영 정책
예: 신청 승인·거절, 문의 분류, 위험 거래 판정
- 먼저 물을 것: 규칙끼리 부딪칠 때 우선순위 / 애매하면 사람에게 넘기는지 / 판정 이유를 누구에게 보여주나
- 첫 단위: 규칙 표(조건 → 결과 → 이유)와 판정 함수, 규칙마다 테스트
- 검증: 규칙마다 통과·거절 예시, 경계값, 판정 이유가 결과와 같이 남는지
- 함정: 규칙을 코드 여기저기 흩뿌림(표 하나로 모은다), 이유 없는 거절

## 분석·리포트
예: 실적 비교, 추세, 원인 분석
- 먼저 물을 것: 비교 기준(기간, 대상, 단위·통화) / 지표 정의(전년 대비, 누적 등) / 누구에게 무슨 결정을 돕는 보고인지
- 첫 단위: 핵심 숫자 하나를 재실행 가능한 스크립트로
- 검증: 작은 범위 손계산 대조, 같은 명령으로 같은 숫자
- 함정: 기간 기준이 서로 다른 자료 섞기, 단위 혼동, 상관을 원인으로 단정
- 더 보기: steps/06_data.md

## 품질·모니터링 데이터
예: 측정값 추세, 장비 이상 탐지, 변경 전후 비교
- 먼저 물을 것: 정상 범위와 단위 / 이상으로 볼 기준 / 오탐과 놓침 중 무엇이 더 나쁜가
- 첫 단위: 기준선 통계(평균, 범위)와 이상 판정 하나
- 검증: 알려진 정상·이상 예시로 판정 확인, 변경 전후 같은 지표 비교
- 함정: 측정 조건이 다른 데이터 섞기, 이상치를 지워서 문제를 숨김

## 안내·교육·질의응답
예: 사내 규정 안내, 학습 도우미, 연습 코칭
- 먼저 물을 것: 근거로 삼을 문서 범위 / 모르는 질문에 어떻게 답해야 하나 / 대상의 수준
- 첫 단위: 근거 문서를 찾아 보여주는 흐름 하나 (답에 출처 표시)
- 검증: 고정 질문 세트로 답과 출처 확인, 범위 밖 질문에 "모른다" 처리
- 함정: 근거 없는 답(지어내기), 외부 AI 키를 코드에 넣기, 질문 세트 없이 "잘 된다"고 판단

## 화면 중심 프로토타입
예: 웹 게임, 시뮬레이션, 인터랙티브 도구
- 먼저 물을 것: 꼭 느껴져야 하는 핵심 경험 하나 / 규칙(승패, 점수, 종료 조건) / 지금 버려도 되는 것
- 첫 단위: 핵심 상호작용 하나가 화면에서 실제로 동작
- 검증: 화면 로직과 규칙 로직을 나눠 규칙은 테스트로, 난수는 고정 시드로 재현, 직접 플레이 확인
- 함정: 꾸미기에 시간 쓰기, 규칙이 화면 코드에 섞여 테스트 불가
