# 채점에 대해 알려진 것

출처 표시: [공식] Cofa 공식 사이트·공개 목업, [응시 안내] 응시자 안내문, [영상] Probe 개발팀 인터뷰, [후기] 다른 대회 참가 후기, [추정] 내 해석.
요약을 거친 내용이라 원문과 문구는 다를 수 있다.

## 세 축 [공식]

| 축 | 질문 | 세부 |
| --- | --- | --- |
| 기술 | AI를 활용해 제대로 작동하는 결과물을 만드는가 | 산출물을 직접 실행하고 검증 / 유지·확장 가능한 구조 / 민감정보와 보안 위험 관리 |
| 의도 | AI를 원하는 방향으로 이끄는가 | 목표와 제약을 명확히 정의 / 작업을 나누고 AI에 위임 / 진행에 따라 방향과 우선순위 조정 |
| 인지 | 결과의 원리와 한계를 이해하는가 | 구조를 선택한 이유 설명 / 실제 구성과 동작 방식 이해 / 한계와 실패 조건 예측 |

인지 축은 제출 후 서술형("이 패턴을 왜 썼나" 같은 질문)으로 확인한다 [영상]. 서술형 답은 실제 구현과 대조된다 [공식].

## 감점으로 알려진 행동

- 과제 지시서를 그대로 붙이고 "다 만들어줘" [영상]
- AI가 과하게 만든 것(요구에 없는 가드, 기능)을 그대로 두기 [영상]
- 업무 담당자에게 "할 일 1, 2, 3 알려주세요"처럼 답을 통째로 요구 [영상]
- 한 번에 다 만들게 하고 몇 시간씩 고치기 [영상]
- 서술형에서 그럴듯하게 지어내기 [공식]
- 같은 요청 반복, 확인 없이 AI 결과 받아들이기 [추정]

## 가점으로 알려진 행동

- 사소한 질문부터 차근차근 맥락 모으기 [영상]
- 토큰을 적게 쓰면서 좋은 결과 [영상]. 토큰 사용량은 간접 평가에 참고될 수 있다 [응시 안내]
- 수정 전에 원인과 계획 공유, 실패 상황도 함께 검증 [공식 목업의 담당자 메시지]
- 평소 쓰던 스킬·작업 방식을 가져와 쓴 참가자의 상위권 사례 [영상]
- 응답 대기 시간을 고려한 위임과 시간 안배 [응시 안내]
- 다른 사람이나 새 세션이 이어받을 수 있게 정리(handoff) [후기, 다른 대회 일부 트랙의 축]

## 수집되는 기록 [응시 안내]

에이전트·담당자 대화, 터미널, AI 도구 설정, git log, diff, 테스트 실행 결과, 작업 공간 파일, 토큰 사용량. 실행 화면도 근거로 본다 [영상].
문서에 적힌 말과 실제 코드·커밋이 맞는지 대조한다 [후기].

## 문서 [응시 안내]

계획 문서, 협업 기록 같은 제출 문서는 Codex와 같이 써도 불이익이 없다. 판단, 근거, 검증 결과, 남은 한계가 담겨야 한다.

## 규칙 [응시 안내]

- AI는 응시 환경의 Codex만. Codex 업데이트 금지
- 공개 저장소의 지침·Skill·하네스·템플릿·코드 활용 가능 (결과 통지 전까지 공개 유지). 비공개 저장소, 결과물 통째 대체는 불가
- 개인 파일 업로드, git push 불가
- 서술형: AI 금지, 복사·붙여넣기 불가, 이전 문항 복귀 불가. 제출물과 작업 기록으로 생성. 질문의 전제가 실제 구현과 다르면 차이를 밝히고 설명
