# 07 검증과 정리 · 남음 0:45부터, 08과 시간을 반씩 · 여기서부터 새 기능 금지

AI 설명이 아니라 실행 결과로 믿는다. 이 단계의 기록이 서술형 "무엇을 근거로 믿나"의 답이 된다.

## 할 일

1. 동시에 두 개
   - 터미널 2: `bash work-kit/tools/check.sh full` → FAIL부터 처리
   - Codex: 필수 요구 대조
   ```text
   PLAN 필수 요구마다 실제 확인 결과를 PLAN에 써줘: 통과(근거 명령·테스트) / 미완 / 가정.
   실행하지 않은 건 미실행이라고 써. 비어 있는 요구가 있으면 tests/나 checks/에 검증을 추가해.
   ```
2. 일부러 깨뜨려 보기 (핵심 요구 3~5개만)
   ```text
   필수 요구 (번호)를 일부러 어기는 입력을 만들어서 검증이 실패하는 걸 보여줘. 확인 후 원래대로 돌려놔.
   ```
   빨간불이 안 뜨는 검증은 고친다
3. 과제가 입력이나 설정을 바꿔 다시 돌리는 기능을 요구하면: 경계값·극단값 1~2개로 다시 돌려 본다. 핵심 로직이 있으면 기준선 대비 개선 비교표가 notes/에 있는지 확인 (서술형 근거)
4. 화면이 있으면 직접 눌러 본다 (미리보기, 서버는 0.0.0.0). 역할이 있으면 역할마다 한 번씩
5. 실행 조건 점검: 과제가 운영 환경 조건을 요구했으면 ref/deploy.md. 오래 걸리는 확인은 checks/full/에 스크립트로
6. 걷어내기 (시간이 남을 때만)
   ```text
   리뷰어 입장에서 요구에 없는데 들어간 코드와 위험 3가지(동작, 보안, 유지보수)만 짚어줘. 수정은 하지 마.
   보안은 SQL 값 바인딩, 권한 검사가 서버에 있는지, 에러 응답에 내부 정보(스택트레이스, 경로)가 없는지를 본다.
   ```
   제일 아픈 것 하나만 고치고, 걷어낸 건 DECISIONS "걷어낸 것"에 이유와 함께
7. 커밋

## 끝 기준

- check.sh full에 FAIL 없음 (WARN은 이유를 안다)
- 필수 요구마다 통과·미완·가정이 적혀 있다

점수 연결: 산출물 직접 실행·검증, 보안 (기술) · 한계와 실패 조건 예측 (인지)
