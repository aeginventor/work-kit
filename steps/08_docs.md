# 08 제출 문서 · 21:35 ~ 21:50

서술형은 이 문서들과 코드에서 나온다. 그리고 문서에 적힌 말과 실제 코드·커밋이 맞는지 대조된다.
초안은 Codex가 쓰고, 사실 확인과 최종 문장은 내가 한다.

## 할 일

1. notes/deliverables.txt 목록 기준으로 하나씩. 양식이 정해진 문서는 제목과 순서를 그대로, 해당 없는 칸은 "해당 없음"
2. 실행 안내 문서 (과제가 정한 이름으로)
   ```text
   (실행 안내 파일)을 과제 양식대로 채워줘. 이번에 실제로 실행해서 확인한 명령만 써.
   설계 기준, 가정, 알려진 한계는 notes/DECISIONS.md와 PLAN에서 가져와. 확인 못 한 건 미확인이라고 써.
   ```
   그다음 내가 터미널 2에서 그 순서대로 따라 쳐 본다. 채점자도 그대로 따라 한다
3. AI 협업 문서 (과제가 요구하면): 이 문서에서 서술형이 여러 문항 나올 수 있다. 내가 쓴다
   - 먼저 Codex에 `notes/DECISIONS.md "AI 협업 경위"와 git log에서 질문별로 쓸 만한 실제 사건 후보만 목록으로 줘. 사건마다 관련 커밋과 파일`
   - 사건을 골라 내 말로 쓴다: 본 것 → AI가 말한 것 → 내가 확인한 것 → 받아들임/고침/버림과 근거
   - 다 쓰면 `이 문서의 사실이 git log·코드와 맞는지만 확인해줘. 문장은 고치지 마`
4. notes/HANDOFF.md 최종 갱신: `HANDOFF.md를 지금 코드와 git log 기준으로 채워줘`
5. 문서와 실제 대조 (채점이 문서의 말과 코드·커밋을 대조한다)
   ```text
   제출 문서와 notes/의 문장 중 코드·명령·테스트로 확인할 수 있는 주장을 실제와 대조해줘.
   틀리거나 과장된 문장 목록만 R 번호와 함께. 고치지는 마.
   ```
   목록대로 고치고, 내가 설명 못 하는 용어는 지우거나 쉬운 말로 바꾼다
6. `bash work-kit/tools/check.sh` → 제출물 WARN 없음 확인
7. 제출 폴더 정리: `git status -s`, `ls`, `du -sh * | sort -h | tail` 로 훑는다. 내가 설명 못 하는 스크립트·문서, 쓰다 만 실험 파일은 지우거나 이유를 HANDOFF에 적는다. 큰 설치 폴더(node_modules 등)가 섞였는지 본다
8. 에디터 탭이 모두 저장됐는지 확인 → 최종 커밋 → `git status -s` 가 비어 있는지

- deliverables.txt의 파일이 모두 있고 양식을 지켰다
- 실행 안내를 내가 따라 쳐 봤다
