# 09 제출과 서술형 · 21:50 예상 질문 · 22:00 제출

## 제출 전 (8분)

1. 예상 질문 뽑기
   ```text
   이 작업공간의 제출물, notes/, git log를 처음 보는 평가자라고 생각하고 서술형 질문 6개를 내줘.
   내 결정 카드, 코드의 핵심 흐름, 검증 기록, 협업 경위 중에서 가장 물을 만한 것으로. 답은 쓰지 마.
   ```
   그중 제일 자신 없는 1~2개는 Codex 창에 내 말로 3~4줄 답을 직접 쳐 보고
   `내 설명이 실제 코드와 다른 사실만 짚어줘. 고쳐 쓰지는 마` → 틀린 사실만 머리에 넣는다
   나머지는 머릿속으로만
2. notes/DECISIONS.md 결정 카드, 방향 조정, 걷어낸 것, AI 협업 경위를 한 번 훑는다
3. 상단 "제출하고 문제풀기" → 미리보기에서 제출물 확인 → 확정 (이후 수정 불가)

## 서술형 (문항당 5분, 복붙 불가, 이전 문항 복귀 불가, 시간 끝나면 자동 확정)

문항마다: 1분 읽고 전제 확인 → 3분 쓰기 → 1분 다듬기. 핵심 문장부터 쓴다.

```text
(전제) 질문은 ○○라고 했지만 실제 구현은 △△입니다.      ← 전제가 맞으면 생략
(결론) ○○를 했고, 한마디로 □□ 때문입니다.
(근거) 요구사항 ○번 / 담당자 답 / 데이터에서 본 것
(증거) ○○ 파일의 △△, ☆☆ 테스트·명령 결과
(대안) ◇◇도 봤지만 ▽▽ 때문에 버렸습니다.
(한계) 감수한 것은 ○○이고, 더 한다면 △△를 확인하겠습니다.
```

- 모르면 지어내지 않는다: "이 부분은 확인하지 못했습니다. 확인하려면 ○○를 돌려 보겠습니다"
- 질문이 틀에 안 맞으면 결론 → 증거 → 한계만이라도

끝: 최종 제출과 종료 안내를 확인하고 나간다
