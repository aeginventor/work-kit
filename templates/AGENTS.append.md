### 작업 규칙
- 수정 전에 원인과 변경 범위(파일, 함수)를 먼저 보고하고 내 확인을 기다린다
- 작업 계획의 한 단위만 진행하고, 끝나면 멈춰서 결과를 보고한다
- 내가 지정한 파일 외에는 건드리지 않는다
- 요구사항에 없는 기능, 가드, 추상화, 의존성을 추가하지 않는다
- 기존 구조와 코드 스타일을 따른다. 같은 로직을 두 군데에 복사하지 않는다
- 기존 API 계약과 응답 형식은 바꾸지 않는다
- 판정과 계산은 코드로 하고, LLM은 해석과 초안에만 쓴다
- 실패를 조용히 삼키지 않는다. 에러는 기존 응답 형식으로 돌려준다
- 비밀값(키, 토큰, 비밀번호)은 환경변수로만 다루고 코드, 로그, 문서에 남기지 않는다
- 서버는 0.0.0.0에 바인딩한다
- 수정 후 같은 테스트를 다시 돌리고 결과를 보여준다. 정상 경로와 실패 경로 둘 다
- 레포 전체를 읽지 말고 필요한 파일만 읽는다. work-kit/ 폴더는 과제와 무관하니 읽지 않는다
- 모르는 건 추측하지 말고 묻는다

### 완료의 정의
- 성공 기준마다 확인하는 테스트나 재현 방법이 있고 통과한다
- 전체 테스트가 통과한다
- 비밀값이 코드와 로그에 없다
- DECISIONS.md에 판단, 근거, 검증 결과, 남은 한계가 있다
- HANDOFF.md만 읽고 다른 사람이 실행하고 이어서 작업할 수 있다
